# MCP 工具與 prompt

[English](tools.md) | **繁體中文**

`pobg` server 提供給 AI 用戶端的功能。玩家不需要自己呼叫，由助理挑選使用。把它們串起來的流派流程寫在
[`src/tools/build_workflow.py`](../src/tools/build_workflow.py)（也是 `build_guide` prompt 與 `build_workflow`
工具的內容），Claude Code 則寫在 [`skills/poe2-advisor/SKILL.md`](../skills/poe2-advisor/SKILL.md)。

## 工具

| 工具 | 回答什麼 |
|---|---|
| `lookup_entity` | 名稱（英文／繁中）→ 實體、種類、兩個 poe2db 網址 |
| `get_gem`、`get_passive`、`explain_keyword` | 單筆紀錄與其來源 |
| `passives_with_stat` | 哪些天賦提供某個屬性 |
| `gems_by` | 依標籤、階級、職業、武器、種類或關鍵字篩選寶石 |
| `supports_for` | 可以輔助某技能的所有輔助寶石 |
| `reference_builds` | 天梯角色在用什麼（職業、主技能、排名、寶石、keystone；不含角色名稱）；流派回答用它說明生成的流派與天梯主流差在哪，而不是用它來決定流派 |
| `verify_build` | 檢查流派草稿裡的寶石、天賦、裝備與目標詞綴（「戒指：+#%火焰抗性」，要寫完整詞綴；每件裝備最多 3 條前綴、3 條後綴；只寫部分的詞綴會回傳候選）；回傳事實、被移除的名稱與排好的來源清單 |
| `path_to` | 從職業起點點到目標天賦要依序點哪些節點；對照 123 / 8 點上限，並加總整條路線的屬性（近似路線） |
| `export_pob` | Path of Building 匯入碼：職業、昇華、`path_to` 的路線、技能組（「技能: 輔助, 輔助」）、裝備（「部位: 物品; 詞綴; 詞綴」）與 PoB 配置選項；查無的名稱、不能輔助該技能的輔助寶石、該物品出不了的詞綴不會放入，改列在 `not_exported`。見[下方](#export_pob) |
| `get_item` | 一件裝備基底（數值、需求、固定詞綴）或傳奇（其詞綴），附來源 |
| `items_by` | 依裝備類別、種類、需求等級或文字篩選基底與傳奇 |
| `modifiers_for` | 某類裝備（或某基底、傳奇所屬類別）能出哪些詞綴：依族群分組，列出每一階的等級與數值範圍、前綴或後綴；也包含褻瀆、精髓、腐化與鑲嵌物的效果 |
| `build_workflow` | 有出處的流派回答流程，給不支援 MCP prompt 的用戶端使用 |
| `refresh_gem` | 重新抓取 poe2db 上的一顆寶石頁面並取代本機紀錄 |
| `data_status` | 本機資料有哪些、多舊；需要時可檢查線上網站 |
| `update_data` | 重新抓取一類資料（必須指定範圍：三種寶石、天賦、裝備、名詞解釋、天梯），每次呼叫的請求數有上限 |

Prompt：`build_guide`（流派流程）、`status` 與 `update`（資料指令，見 [data.zh-TW.md](data.zh-TW.md#指令)）。
只有 `refresh_gem` 與 `update_data` 會變更資料；其餘十六個工具都標示為唯讀，其中只有 `data_status` 在被要求檢查線上網站時會連網。

## `export_pob`

不寫入任何檔案，也不發出網路請求。回傳 `code`、`how_to_import`、`notes`（也寫進 PoB 的備註頁）、`not_exported`
與 `summary`：

| summary 欄位 | 由什麼算出 |
|---|---|
| `level` | 用掉的天賦點，依 PoB 自己的等級公式與章節表（123 點為 100 級），或使用指定的 `character_level` |
| 寶石等級 | 每顆技能寶石取等級表中角色等級可用的最高一列（最高 20）；輔助寶石沒有等級 |
| `attributes` | 各屬性的已有／需求。需求：各技能寶石需求的最大值、輔助寶石「+N」增加量的總和、裝備需求的最大值，三者取最大。已有：職業基礎值加上天賦與裝備上的固定屬性。路線上的屬性天賦點優先補足寶石與裝備的需求，或依指定的 `attribute`。不計入百分比增加與需求降低 |
| `spirit` | 已有／需求，算法與 PoB 相同。需求：（每個常駐技能的保留量 + 其輔助寶石的額外保留量）× 輔助寶石的保留倍率，四捨五入；改為保留生命的輔助寶石計為 0。資料只給出隨寶石等級變動範圍（召喚物技能）或完全沒給保留量的技能，列在 `unknown`。已有：所有精魂任務獎勵（PoB 預設）、權杖的基礎精魂、裝備與天賦上的固定「+N 精魂」 |
| `config` | 每個開啟的 PoB 配置選項及其依據（寶石、天賦、裝備詞綴或名詞解釋規則） |

**裝備**的檢查方式與 `verify_build` 相同：基底與傳奇對照本機資料，稀有裝備的詞綴對照該類裝備能出的詞綴
（3 條前綴 + 3 條後綴，同族群只能一條），以最高階的上限寫入。副手規則依照 PoB。藥劑與護符會設為啟用。不匯出品質、
符文與靈魂核心、插槽與珠寶；有 13 個基底與 11 件傳奇在 PoB 中沒有同名的對應，PoB 不認得的基底或詞綴會被略過或標為不支援。
稀有裝備的名稱是單純的標籤（「POBG Ring 1」）：遊戲中的稀有名稱是隨機產生的，PoB 也不使用。沒有武器時，攻擊技能會顯示為停用。

**配置**（預設 `config=True`）：只有流派本身有依據時才開啟：

- 流派會獲得的球（只消耗球或只改變上限的不算）；
- 流派會造成的敵人狀態（只從中得益、消耗、加重，或只改變機率的不算）；「無法……」的句子會讓該技能組不計入該狀態或球；
- 感電、冰緩、點燃：依名詞解釋的規則，由該元素的傷害技能造成（增益、光環、詛咒等不會擊中的技能不算）；攻擊流派也看主手武器的元素；
- 曝曬：依句子內容或寶石標籤判斷元素；需要近期暴擊的屬性會開啟「近期暴擊」。

球類以 PoB 的最大顆數計算（「數量（如果不是最大值）」欄留空）。備註會列出 poe.ninja 天梯匯出對每個角色都假設開啟、
但本流派沒有來源的選項。這些規則是對遊戲文字的比對，已對全部寶石與天賦稽核過；它們必須符合的句子見
`tests/unit/test_config_rules.py`。
