# 計畫：章節之後接上輿圖（T1 → T10 → T16）

版本 0.15.0。沒有你的指示不 commit、不推送。

## 背景

0.13.0 的流派只排到章節結束。社群說的「拓荒」是打完章節後能直接進輿圖並一路打上去，所以章節之後還缺一段。

你的決定（2026-11-17）：

- 這件事**優先於**傳奇裝備與傳奇珠寶。
- 目標預設打到 **T16**；不考慮輿圖天賦與其他加難度的機制，地圖只到白圖、魔法圖、稀有圖。
- 輿圖分**三段：T1、T10、T16**。
- **範圍到 T16 為止，後期王戰不放進來**：不收集、不規劃巔峰頭目、城塞與地圖頭目的內容；流派也不以打王為目標。
- **收集換界石詞綴**，流派列出要避開的詞綴。

## 調查結果（實際讀了 poe2db `/us/Waystones`，2026-11-17）

| 頁面上有的 | 內容 |
|---|---|
| 換界石階級 → 區域等級 | T1 = 65、T10 = 74、T15 = 79、T16 = 80（共 16 階） |
| 抗性懲罰表（Level Resist Penalty） | 1 級 0、16 級 −10、33 級 −20、45 級 −30、54 級 −40、60 級 −50、65 級 −60 |
| 換界石詞綴 | 107 個，有前綴／後綴與效果文字（怪物額外火焰傷害、怪物暴擊、怪物生命等） |
| 混沌試煉長度 | 1 級 4 關、60 級 7 關、75 級 10 關（`/us/The_Trial_of_Chaos`） |

- 抗性懲罰表順便補上章節流派原本寫「資料沒有」的那一項。
- **頁面上沒有的**：T16 怎麼取得（你說的瓦爾寶珠腐化 T15，poe2db 這頁沒寫，計畫中不當成資料）、後期昇華點（第 5–8 點）對應哪個試煉、怪物的實際傷害與生命。
- 1.0 預定 2026-12-11 上線，階級與數字可能變，所以三段的區域等級**由資料產生**，不寫死。

## 這一版做得到與做不到的

- **做得到**：每一段給出資料上的上限與條件：等級、天賦點、寶石等級與插槽、該物品等級出得了的詞綴階級、抗性懲罰、依資料看得出會剋制這個流派的地圖詞綴；T16 那段與天梯角色完整比較。
- **做不到**：專案不計算傷害與生存，所以**無法證明**「這個流派打得過 T16」。回答會明說，並請你匯入 PoB 看抗性與數值、進遊戲實測。

## 做法

### 1. 新資料：`atlas` 範圍

- `src/scrapers/collect_atlas.py`（新），仿照 `collect_currency.py` 的結構（解析 → 合併 → 檢查 → 寫入），讀 `/us/Waystones` 與 `/tw/Waystones`（2 個請求）：
  - `data/atlas/atlas.json`：階級表（階級、區域等級、中英名稱）、抗性懲罰表、來源網址與抓取時間。
  - `data/atlas/waystone_mods.jsonl`：每個詞綴的前綴／後綴、效果文字（中英）、來源。中英對不上的詞綴只留英文，比例過低就不寫入。
- `src/catalog/poe2db_sources.json` 新增 `atlas` 來源：頁面、檔案、`stage_tiers: [1, 10, 16]`、`expect_min`（階級 ≥ 10、詞綴 ≥ 60、懲罰表 ≥ 5 列、中文比例 0.8）。
- 後期昇華點：比照既有的 `ascendancy_trials`（人工查證後寫在目錄裡並註明日期），新增「60 級起 +2、75 級起 +2」。**實作時先查證**（poe2db 昇華頁或官方說明）；查不到就維持章節的 4 點，並在 `not_in_data` 說明後期昇華點不在資料裡。
- `src/tools/maintenance.py`：`atlas` 更新範圍，整份重抓（沿用 `WHOLE_SET_SCOPES` 的做法，不需分批）；`data_status` 回報。

### 2. 階段表加上輿圖三段

- `src/tools/campaign.py`：`CampaignLookup` 讀到 atlas 資料時，在章節階段之後接上 `maps_t1`、`maps_t10`、`maps_t16`（由 `stage_tiers` 與階級表產生），每個階段多一個 `kind`（`campaign` / `maps`）。
  - 等級沿用現有規則：階段的區域等級（65 / 74 / 80）。天賦點、寶石等級、輔助階級、插槽照 `stage_limits` 現有算法，不需新邏輯。
  - 所有階段（含章節）的 `limits` 加 `resistance_penalty`，取自懲罰表；`NOT_IN_DATA` 移除「抗性懲罰」那行。
  - `find_stage` 認得 `T16`、`tier 16`、`第 16 階`。
- 因為 `path_to(by_stage)`、`export_pob(stage)`、`verify_build(character_level)` 都是讀階段表（`build_tools.py:735` `_stage_cuts`、`:1159` `_stage_trees`），接上後**自動**支援輿圖段：匯入碼會有每一段的天賦樹，裝備詞綴用該物品等級出得了的階級。
- 沒有 atlas 資料時，行為與現在完全相同（只有章節階段），並提示執行 `update atlas`。

### 3. 新工具 `waystone_mods`（唯讀，24 → 25 個）

- `src/tools/atlas.py`（新，`AtlasLookup`）：依文字（中英）與前綴／後綴篩選換界石詞綴，附 poe2db 連結與抓取日期；`mcp_server.py` 註冊。
- `not_in_data`：怪物實際傷害與生命、頭目打法、T16 的取得方式、輿圖天賦與石板、哪個詞綴「一定打不過」。

### 3b. 新工具 `search_string`：遊戲內搜尋字串（唯讀，共 26 個工具）

你的要求（2026-11-17）：章節段的裝備建議附上遊戲內搜尋用的字串；輿圖段著重在地圖，讓玩家在一堆換界石裡很快找到能打的。

**查到的語法**（社群指南，非官方文件）：只能用在倉庫與商人視窗；整串用引號包住；`|` 是「任一個」；`!` 是排除；空格是「同時符合」。它不是完整的正則表達式，所以**只用文字片段加 `|` 與 `!`**，不用其他語法。字數上限說法不一（250 字，舊版較短），放在目錄設定裡，可調整。

**做法**：字串由程式從資料算出，不由模型自己寫（`src/tools/search_string.py`，新）。

| 用途 | 輸入 | 產生 |
|---|---|---|
| 裝備（章節與輿圖段） | 裝備類別 + 想要的詞綴（`modifiers_for` 顯示的整行） | 每個詞綴取**最短、且不會配到同類別其他詞綴**的文字片段，用 `\|` 串起來：符合任一個想要的詞綴就亮起 |
| 地圖（輿圖段） | 要避開的換界石詞綴 | `!片段\|片段`：含有任一個要避開詞綴的換界石不亮，剩下亮著的就是能打的 |

- 片段不含數字（數值會變動），並對照資料裡**全部**詞綴檢查：誤配到的詞綴列在 `also_matches`，找不到唯一片段時照實說。
- 超過字數上限時拆成多串，每串都能單獨使用。
- **中英文各一串**：字串必須跟遊戲客戶端的顯示文字一致，所以依資料的英文與繁中文字各產生一串。
- 流程：章節段每個裝備欄位（或該階段合併一串，方便逛商人）附搜尋字串；輿圖段每段附一串地圖搜尋字串。
- **無法在本機驗證的**：字串在遊戲裡是否真的生效、繁中客戶端的用字是否與 poe2db 完全相同。第一版需要你在遊戲裡貼上實測，結果寫進測試報告。

### 4. 流派流程（`build_workflow.py`、`skills/poe2-advisor/SKILL.md`）

- **預設目標改為：章節 + 輿圖三段，到 T16 為止。** 使用者說只要章節時，只排章節；指定高於 T16 的等級或要完成品時，走現有的後期流程（不變）。
- 順序：先排 T16 的成品，再往回排 T10、T1 與各章節。
- 輿圖段每段固定寫：等級與點數 → 技能與輔助 → 天賦 → 裝備（基底與該物品等級的詞綴目標）→ **抗性懲罰**（數字來自 `campaign_stages`；抗性上限要用 `lookup_entity` 查到才寫）→ **要避開的換界石詞綴**。
- 避開詞綴的規則：只列效果文字直接對應到這個流派**已驗證**內容的詞綴（例如流派靠暴擊，而詞綴降低怪物受到的暴擊傷害），原文引用並附出處；不宣稱其他詞綴安全。
- 天梯比較：章節段仍只比主技能與昇華；T16 段完整比較。
- 回答結尾明說：傷害與生存沒有計算，匯入 PoB 檢查抗性是否補滿懲罰。

## 錯誤處理

- 頁面格式變了或 1.0 改了階級：檢查不過就不覆寫舊資料；`stage_tiers` 裡的階級在頁面上找不到時，回報哪一階不存在，不自己挑別的。
- atlas 資料不存在或讀不了：階段表退回只有章節，並說明原因。
- 中文頁失敗：不寫入，舊資料保留。
- 沒有任何換界石詞綴對應到流派內容：照實說「資料上看不出特別要避開的」，不硬湊。

## 驗收

1. 沒指定範圍時，得到章節各段加 T1、T10、T16 三段的流派，每段的上限都有來源。
2. 每個輿圖段寫出抗性懲罰與要避開的換界石詞綴（或說明資料上看不出）。
3. 匯入碼可匯入 PoB，含每一段的天賦樹。
4. 說「只要章節」時，結果與 0.14.0 相同；要完成品時走原本的後期流程。
5. 回答明說沒有計算傷害與生存。
6. 章節段的裝備建議附搜尋字串，輿圖段附地圖搜尋字串；你在遊戲的倉庫或商人視窗貼上後，亮起的是想要的裝備／能打的地圖。

## 實作補記（2026-11-17）

- **後期昇華點**：poe2db `/us/Ascendancy_class` 的社群 wiki 段落有 Trial Type 表（Ascension 2／4／6／8 對應等級 22／38／60／80，「Total 8 Ascendancy points」）。寫進目錄 `atlas.endgame_trials`，註明人工查證日期；**只套用在地圖階段**，章節階段的輸出與 0.14.0 相同。該頁也說第三組在進地圖前就能拿，回答時由 `how` 說明。
- **試煉中文名**：用資料裡的正式譯名（絲克瑪試煉、混沌試煉），不自己翻。
- **地圖階段的區域範圍**：T1 為 [65, 65]，T10 為 [66, 74]，T16 為 [75, 80]。
- **沒有 atlas 資料時**：階段表只有章節，`maps_note` 提示執行 `update atlas`，`not_in_data` 保留抗性懲罰那行。
- **搜尋字串的片段規則**（實測真實資料後調整）：只比對詞綴時，最短的唯一片段會是「n m」「上的」這種很容易配到其他文字的東西。改成：英文只取完整單字（可連續多字），長度至少 4，不取單一虛詞或 increased／more 這類幾乎每條詞綴都有的字；中文只取連續中文字，不以「的、上、有」等字開頭或結尾；先從詞綴第一行（它的效果）找，再看其他行；另外對照該類別的基底名稱（裝備）或換界石階級名稱與標籤（地圖）。真實資料的例子：靴子 `"maximum life|fire resistance|cold resistance|speed"`、`"大生|焰抗|冷抗|動速"`；地圖避開詛咒與暴擊 `"!curses|hits"`、`"!咒具|外傷"`。
- **地圖詞綴的比對**：除了文字片段，也接受「不寫數字、但所有單字都在該行」的寫法（例如 `Monsters deal of Damage as Extra Fire`）；一個輸入對到超過 6 個詞綴時要求寫得更完整。
- **export_pob 的第一行備註**：由「Campaign stage …／章節階段 …」改為「Stage …／階段 …」。
- **未在本機驗證**：字串在遊戲裡是否生效、繁中客戶端的用字是否與 poe2db 相同，需要你進遊戲貼上實測。
- **驗收 4 的修正**：「只要章節時與 0.14.0 相同」並不完全成立：每個階段多了 `kind`，有輿圖資料時多了 `resistance_penalty`、`not_in_data` 少了抗性懲罰那行，PoB 備註第一行改為「階段 …」。其餘（等級、點數、寶石、插槽、天賦樹）相同。CHANGELOG 已註明。
- **複查後的調整**：搜尋字串改為優先取多個英文單字或三個中文字（在一段中文的開頭或結尾），檢查範圍擴大到所有詞綴群組與基底的固定詞綴、屬性標籤；換界石的標籤改由頁面取得（原本手寫，還有一個自己編的中文字）；`waystone_mods` 的 `text` 或 `id` 可以直接給 `search_string`。真實資料例子更新為：地圖避開詛咒與暴擊 `"!less effect|extra damage"`、`"!少效果|外傷害"`；靴子 `"to maximum life|fire resistance|cold resistance|increased movement"`、`"大生命|火焰抗|冰冷抗|動速度"`。
