# 計畫：章節之後接上輿圖（T1 → T10 → T16）

版本 0.15.0。沒有你的指示不 commit、不推送。

## 背景

0.13.0 的流派只排到章節結束。社群說的「拓荒」是打完章節後能直接進輿圖並一路打上去，所以章節之後還缺一段。

你的決定（2026-11-17）：

- 這件事**優先於**傳奇裝備與傳奇珠寶。
- 目標預設打到 **T16**；不考慮輿圖天賦與其他加難度的機制，地圖只到白圖、魔法圖、稀有圖。
- 輿圖分**三段：T1、T10、T16**。
- **範圍到 T16 為止，後期王戰不放進來**：不收集、不規劃巔峰頭目、城塞與地圖頭目的內容；流派也不以打王為目標。
- **收集換界石詞綴**，流派列出要避開的詞綴。

## 調查結果（實際讀了 poe2db `/us/Waystones`，2026-11-17）

## 這一版做得到與做不到的

- **做得到**：每一段給出資料上的上限與條件：等級、天賦點、寶石等級與插槽、該物品等級出得了的詞綴階級、抗性懲罰、依資料看得出會剋制這個流派的地圖詞綴；T16 那段與天梯角色完整比較。
- **做不到**：專案不計算傷害與生存，所以**無法證明**「這個流派打得過 T16」。回答會明說，並請你匯入 PoB 看抗性與數值、進遊戲實測。

### 3b. 新工具 `search_string`：遊戲內搜尋字串（唯讀，共 26 個工具）

你的要求（2026-11-17）：章節段的裝備建議附上遊戲內搜尋用的字串；輿圖段著重在地圖，讓玩家在一堆換界石裡很快找到能打的。

**查到的語法**（社群指南，非官方文件）：只能用在倉庫與商人視窗；整串用引號包住；`|` 是「任一個」；`!` 是排除；空格是「同時符合」。它不是完整的正則表達式，所以**只用文字片段加 `|` 與 `!`**，不用其他語法。字數上限說法不一（250 字，舊版較短），放在目錄設定裡，可調整。

**做法**：字串由程式從資料算出，不由模型自己寫（`src/tools/search_string.py`，新）。

| 用途 | 輸入 | 產生 |
|---|---|---|
| 裝備（章節與輿圖段） | 裝備類別 + 想要的詞綴（`modifiers_for` 顯示的整行） | 每個詞綴取**最短、且不會配到同類別其他詞綴**的文字片段，用 `\|` 串起來：符合任一個想要的詞綴就亮起 |
| 地圖（輿圖段） | 要避開的換界石詞綴 | `!片段\|片段`：含有任一個要避開詞綴的換界石不亮，剩下亮著的就是能打的 |

- 片段不含數字（數值會變動），並對照資料裡**全部**詞綴檢查：誤配到的詞綴列在 `also_matches`，找不到唯一片段時照實說。
- 超過字數上限時拆成多串，每串都能單獨使用。
- **中英文各一串**：字串必須跟遊戲客戶端的顯示文字一致，所以依資料的英文與繁中文字各產生一串。
- 流程：章節段每個裝備欄位（或該階段合併一串，方便逛商人）附搜尋字串；輿圖段每段附一串地圖搜尋字串。
- **無法在本機驗證的**：字串在遊戲裡是否真的生效、繁中客戶端的用字是否與 poe2db 完全相同。第一版需要你在遊戲裡貼上實測，結果寫進測試報告。

### 4. 流派流程（`build_workflow.py`、`skills/poe2-advisor/SKILL.md`）

- **預設目標改為：章節 + 輿圖三段，到 T16 為止。** 使用者說只要章節時，只排章節；指定高於 T16 的等級或要完成品時，走現有的後期流程（不變）。
- 順序：先排 T16 的成品，再往回排 T10、T1 與各章節。
- 輿圖段每段固定寫：等級與點數 → 技能與輔助 → 天賦 → 裝備（基底與該物品等級的詞綴目標）→ **抗性懲罰**（數字來自 `campaign_stages`；抗性上限要用 `lookup_entity` 查到才寫）→ **要避開的換界石詞綴**。
- 避開詞綴的規則：只列效果文字直接對應到這個流派**已驗證**內容的詞綴（例如流派靠暴擊，而詞綴降低怪物受到的暴擊傷害），原文引用並附出處；不宣稱其他詞綴安全。
- 天梯比較：章節段仍只比主技能與昇華；T16 段完整比較。
- 回答結尾明說：傷害與生存沒有計算，匯入 PoB 檢查抗性是否補滿懲罰。

## 3b 修訂：搜尋字串改用真正的正則表達式（0.15.1，2026-11-18）

### 背景

你用 poe2.re 和 Cabbage Forge 對照後發現（2026-11-18）：我們的字串只有 `|`、`!` 的用法正確，片段的組成方式是錯的。你的決定：**改用真正的正則表達式，並在本機驗證**。

### 錯在哪裡

| 問題 | 例子 |
|---|---|
| 以為遊戲只吃純文字。實際上是**逐行、不分大小寫的正則** | poe2.re：`mage$`、`\d+ fire damage$`、`^\d+% increased armour$`；Cabbage Forge：`^rarity: rare$` |
| 沒有 `$`，分不出詞綴和屬性行 | `physical damage` 也會配到每把武器的 `Physical Damage: 13-18` |
| 片段在數字處切斷，又長又含糊 | 中文「增加物理傷害」和「附加物理傷害」都拿到 `物理傷` |
| 混合詞綴被併成一行比對 | 「增加物理傷害」＋「命中值」其實是兩行 |

### 重新審查後，和上一版計畫不同的地方

我讀了 poe2.re 公開的裝備正則資料（英文與繁中各 2,875 條）來校正設計：

1. **數字寫成 `\d+`，不用 `.*`。** poe2.re 的 2,875 條裡沒有任何一條用 `.*`；跨數字一律用 `\d+`（小數 `[\d.]+`，加號 `\+`）。這比 `.*` 精確，所以文法改成跟它一樣。
2. **保留正負號。** 現有的樣板函式會把 `+(31—33)` 整個吃成 `#`，但遊戲裡那行是 `+33 to Strength`，`^` 錨定時必須知道開頭是 `+`。所以要另寫一個保留正負號的行轉換，不能沿用 `modifier_template`。
3. **同一句話出現在兩個詞綴裡時，正則分不出來，要照實說。** 例如「增加 #% 物理傷害」同時是純詞綴和混合詞綴的一行，遊戲裡顯示也一樣。這種情況不算衝突，改列在 `shared_with`（poe2.re 也是用警告處理）。
4. **魔法物品的名稱含詞綴名**（如「…of Skill」），所以詞綴名稱也要列入「不可誤配」的文字。
5. **最短長度**：poe2.re 英文多為 3–7 字元、中文多為 2 字。我們設英文至少 3、中文至少 2（放在目錄設定，可調）。

poe2.re 的程式碼是 AGPL，不抄；它的資料也不收進專案。只在測試報告裡拿同樣的詞綴人工對照。

### 做法（`src/tools/search_string.py` 重寫，工具介面不變）

### 1. 遊戲顯示的「行」

- 詞綴文字依換行拆成多行；每一階各自代入範圍的最小值與最大值，得到實際會顯示的行（`+31 to Strength`、`+33 to Strength`）。
- 內部另存一份「數字換成單一記號」的形式，用來快速比對；片段裡的 `\d+` 對應這個記號，所以快速比對與真正的正則結果一致，最後再用 `re` 實測一次。

### 2. 片段的文法（只用這幾種）

一行中**連續的一段**，其中數字寫成 `\d+`（該詞綴有小數時 `[\d.]+`），`+` 寫成 `\+`，其他正則符號一律跳脫；可在行首加 `^`、行尾加 `$`。全部小寫。不用 `.*`、`\S`、括號。正負號寫在括號內（會變動）的數字不放進片段。

### 3. 選法與驗證

- 候選由短到長（以輸出的字元數計）；同長度時 `$` 錨定優先，其次 `^`。
- 合格條件：
  - **配到目標詞綴每一階的同一行**（最小值與最大值都要配到）。
  - **配不到其他任何行**：同類別所有詞綴群組的每一行、詞綴名稱、基底名稱、固定詞綴、帶數值的屬性行（`Physical Damage: 13-18`）；換界石則是其他所有換界石詞綴的每一行、階級名稱、`Area Level: 65`。
  - 和目標那一行完全相同的行不算衝突，列在 `shared_with`。
- 混合詞綴：優先選沒有和別的詞綴共用的那一行。
- 找不到完全不衝突的片段時，取衝突最少的，列在 `also_matches`（不變）。
- 每個選出的片段最後都用 Python `re`（不分大小寫）對全部實際行跑一次，結果不符就當成程式錯誤回報，不輸出。
- 組字串照舊：`"a|b"`、`"!a|b"`、上限 250 字、`left_out`、`missing`、`unmatched`。

### 4. 資料沒有、驗證不到的行（照實說明）

稀有度行、物品等級、需求行、稀有物品的隨機名稱，以及換界石的屬性行（物品稀有度、怪物群大小、掉落機率、復活次數）。`not_checked` 會寫明。你能進遊戲時，對一顆換界石和一件裝備按 Ctrl+C 把文字貼給我，我就加進驗證範圍與測試。

另外有一點無法在本機確認：褻瀆、腐化等詞綴在遊戲的搜尋文字裡是否帶後綴（例如「(desecrated)」）。若有，`$` 錨定的片段會配不到它們。列入進遊戲要測的項目。

### 修法

### 1. High：兩道防線（`src/tools/search_string.py`）

**防線一：錨定優先。** 選片段的順序改成：

1. 對齊行尾（`…$`）且不衝突的，取最短；
2. 沒有才用對齊行首（`^…`）的；
3. 再沒有才用不錨定的，並在該列標 `unanchored: true`。

理由：固定行多半以數字、`%` 或特定字結尾（`Item Level: 80`、`Quality: +20%`、`Rarity: Rare`），詞綴行則以自己的文字結尾。對齊行尾的片段，連資料完全沒有的行（稀有物品的隨機名稱）也很難誤配。poe2.re 的英文裝備正則有 44% 用 `$`，可見遊戲裡詞綴行確實以詞綴文字結尾。

**防線二：把已知的固定行加進比對。** 這份清單只用來「排除」，多列不會出錯，少列才有風險。來源必須有依據，不自己翻譯：

| 行 | 英文 | 繁中 | 依據 |
|---|---|---|---|
| 需求行 | `Requires: Level 5, 12 Dex` | `需求: 等級 5, 12 敏捷` | poe2db 物品卡片（中英頁都有）；由每個基底已存的需求等級與屬性重組 |
| 稀有度 | `Rarity: Normal／Magic／Rare／Unique` | `稀有度: …`（值只用資料裡有的詞） | poe2.re `y: r`、Cabbage Forge `^rarity: rare$`；名詞解釋「稀有度」 |
| 品質、物品稀有度 | `Quality: +20%`、`Item Rarity: +40%` | `品質`、`物品稀有度` | 名詞解釋 |
| 換界石屬性行 | `Revives Available: 3`、`Waystone Drop Chance`、`Monster Effectiveness`、`Monster Rarity`、`Pack Size`、`Area Level` | `可用的復活`、`區域等級`；其餘中文寫法**資料沒有** | poe2.re 的換界石正則（`le: N`、`p c`、`r ef`、`r rar`、`k s`）；poe2db 換界石頁 |
| 其他 | `Item Level: 80`、`Corrupted`、`Unidentified` | 資料沒有 | poe2.re `corr`；英文為遊戲通用文字 |

- 清單放在目錄 `atlas.search.fixed_lines`，每一行註明依據；需求行由程式從基底資料產生。
- 中文缺的行不硬補，靠防線一擋；`not_checked` 照實列出哪些中文行沒對照。你之後貼上遊戲裡 Ctrl+C 的文字，我再補進清單。

### 2. Medium：未展開的記號

- 展開範圍後，行裡若還有括號、方括號或「數字—數字」，視為**無法使用**：不拿來切片段。目標詞綴只有這種行時，列入 `missing` 並說明原因。
- 範圍與數字的規則允許千分位逗號（`1,000—1,200`）。

### 3. Medium：找不到片段要說

- 片段為空時，在該語言的 `missing` 加一筆，原因寫明「找不到能和其他行區分的片段」。
- 混合詞綴各階的行改用「文字相同」對齊，不靠行的位置。

### 4. Medium：`shared_with` 註明來源

- 每筆改為 `{line, source}`，`source` 是 `modifier`、`implicit` 或 `unique`。
- 工具說明、工作流程與 skill 的文字同步改：共用的若是基底固定詞綴，代表該基底的每件物品都會亮。

### 5. 順帶修的 Low（改動小、同一個檔案）

- 該行任何數字帶小數時，數字寫成 `[\d.]+`（原計畫就有，實作漏了）。
