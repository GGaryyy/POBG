# 計畫：以「打通章節」為目標的分階段流派

核准後存為 `docs/plan_campaign_build.md`。版本 0.13.0。沒有你的指示不 commit、不推送。

## 背景

現在生成的流派是滿等、最高階裝備的成品，開季時做不出來。你的決定（2026-11-14）：

- 流派生成的目標先限縮為**可以打通章節**，等級、技能、裝備都跟著受限。
- **分階段**呈現（每一章一個階段），第一版出來後你再看細節。
- 裝備：基底 + **該等級出得了的詞綴階級**。
- **章節為預設**；使用者指定等級（例如 90 等）或說要後期流派時，才用現在的做法。

## 調查結果（兩個 agent 上網查證，2026-11-14）

**遊戲現況**
- 現行版本 0.5.5：章節是第 1–4 章 + 3 個插曲，打完約 60–65 等進入輿圖。殘酷難度已在 0.3.0 移除。
- **1.0 預定 2026-12-11 上線**，新增第 5、6 章，插曲會移除。所以階段表**不能寫死在程式裡**，必須由資料產生，更新資料就跟上新版本。

**玩家的開荒指南（讀了 11 份，0.5 版，6 種職業）怎麼寫**
- 幾乎都**按章節分段**；段內換技能的時機由「拿到幾級的未切割寶石」與任務決定，不是等級數字。
- 每段固定會寫：用哪些技能與輔助、精魂與常駐增益、昇華試煉的時機、天賦進度、武器與防禦的優先順序、鞋子移動速度、藥劑與護符、不能漏的任務獎勵。
- 其中屬於**遊戲資料**的（可以由 poe2db / PoB 得到）：寶石階級與等級需求、輔助插槽數、基底的需求等級、詞綴的物品等級、任務獎勵、昇華試煉的區域等級。
- 屬於**遊玩經驗**的（資料裡沒有）：王的打法、哪個技能前期手感差、詞綴的優先順序、刷怪路線。

**每一章有什麼資料**（來源：PoB `QuestRewards.lua`，已在下載；poe2db `/us/Act_1`…`/us/Act_4`、`/us/Interlude`）

| 階段 | 區域等級 | 任務天賦點 | 精魂 | 其他永久獎勵 | 昇華 |
|---|---|---|---|---|---|
| 第 1 章 | 1–15 | 4 | +30 | +20 生命、+10% 冰抗 | – |
| 第 2 章 | 16–31 | 4 | – | +10% 雷抗、+1 護符欄 | 試煉（區域 22）→ 2 點 |
| 第 3 章 | 33–45 | 4 | +30 | +10% 火抗、三選一 | 試煉（區域 38）→ 4 點 |
| 第 4 章 | 46–53 | 4 | – | +5% 魔力、抗性或屬性刺青 | – |
| 插曲 | 54 起 | 6 | +40 | +5% 生命等 | – |

- 技能寶石等級的需求等級在每顆寶石自己的等級表裡（已有）；技能寶石階級 1/3/5/7/9/11/13、精魂寶石 4/8/14 對應要有該等級的未切割寶石。
- 輔助插槽：預設 2；次級／高級／完美工匠石把插槽設為 3／4／5，掉落等級 25／45／65。

**查不到或互相矛盾的**（計畫中不當成事實）：章節後的抗性懲罰時程、插曲的實際區域等級（PoB 與 poe2db 不同）、未切割輔助寶石各階的掉落等級、1.0 的一切細節。

## 做法

原則不變：**數字由資料決定，不由模型推測**；資料沒有的就說沒有。玩家指南的文字不收進專案（無法查證，也有著作權），只用它們來決定「每個階段該交代哪些事」。

### 1. 新資料：章節表（`campaign` 範圍）

- `src/scrapers/collect_campaign.py`（新）：
  - 從 PoB `QuestRewards.lua` 讀**全部**任務獎勵（現在只讀天賦點與精魂）：章節、區域等級、獎勵內容。沿用 `collect_passives.py` 的 `quest_blocks`、`cached_fetch`。
  - 從 poe2db 的章節頁（`/us/Act_N`、`/tw/Act_N`、`/us/Interlude`）讀區域清單：名稱（中英）、區域等級、王。章節數由索引頁 `/us/Act` 決定，不寫死。
  - 從 poe2db 讀未切割寶石的階級表（`/us/Uncut_Skill_Gem`、`/us/Uncut_Spirit_Gem`）與三種工匠石的掉落等級。
  - 輸出 `data/campaign/stages.jsonl`（每階段一筆）與 `data/campaign/rules.json`（寶石階級、插槽），每筆附來源網址與抓取時間。
- `src/catalog/poe2db_sources.json`：登記上述來源；`maintenance.py` 加 `campaign` 更新範圍（約 26 個請求，沿用 0.8 秒間隔；實作時確認：章節頁中英各一、插曲頁、寶石與工匠石頁、未切割輔助寶石的五個等級頁、PoB 任務獎勵），`data_status` 會回報它。
- 階段的角色等級 = 該階段最後一個區域的等級（poe2db）。PoB 與 poe2db 不一致時用 poe2db，並在輸出裡註明。這個取法第一版後可再調整。

### 2. 新工具 `campaign_stages`

回傳每個階段的**上限**與來源，供助理照著排流派：

- 等級、可用天賦點（等級 − 1 + 到此為止的任務點）、昇華點（試煉區域等級 ≤ 階段等級）、任務給的精魂；
- 技能寶石最高等級與可切的階級、精魂寶石階級、輔助插槽數；
- 這一章的永久獎勵（抗性、生命、護符欄、選項）與王的名稱；
- 資料沒有的項目列在 `not_in_data`（例如抗性懲罰），助理必須照實說。

### 2b. 章節問答：玩家問章節細節時也能回答

你的要求（2026-11-14）：章節內容既然收進來了，玩家問章節細節時 AI 也要能用這些資料回答。

**已確認做得到**：實際讀了 poe2db 的 `/tw/Act_1` 與 `/us/Quest`，章節頁本身就有這些內容，中英文都有，不需要每個區域、每個任務各抓一頁：

| 頁面上有的 | 例子 |
|---|---|
| 區域表：名稱、區域等級、王 | 河岸，等級 1，浮腫米勒 |
| 任務清單：主線／支線、目標說明、獎勵 | 險惡之地（支線）：到泥沼陋居擊殺吞噬獸；100 金幣、未切割的輔助寶石 |
| 章節地圖：區域之間怎麼相連 | 皆伐 ↔ 泥沼陋居 |
| 各區域的小節、傳送點、城鎮標記 | 皆伐營地是城鎮 |
| 每個區域與任務在 poe2db 的網址 | 可當出處 |

**做法**
- 章節收集程式另外輸出 `data/campaign/areas.jsonl` 與 `data/campaign/quests.jsonl`（中英文以網址代稱合併），永久獎勵（天賦點、精魂、抗性）以 PoB 的 `QuestRewards.lua` 補上。
- 區域、任務、王的名稱加進實體索引：`lookup_entity` 可以用中文或英文找到它們。
- 新工具：`get_area`（等級、王、相連的區域、在此進行的任務）、`get_quest`（類型、目標、獎勵、所在章節）、`campaign_by`（依章節、種類或獎勵文字篩選，例如「哪些任務給天賦點」「第 3 章有哪些王」）。全部唯讀，附 poe2db 來源。
- `skills/poe2-advisor/SKILL.md` 與 `SERVER_INSTRUCTIONS`：章節問題先查這些工具，照紀錄回答並附出處。

**答得出來的**：某任務給什麼、哪些任務給天賦點／精魂／抗性、某區域幾等、有哪些王、怎麼走到某區域、某一章有哪些支線。

**答不出來的**（頁面上沒有，AI 要照實說）：王的招式與打法、建議的抗性門檻、掉落機率、路線效率。一般怪物只有部分列出。

### 3. 既有工具加上「等級」

| 工具 | 改動 |
|---|---|
| `gems_by`、`supports_for` | 加 `max_level`：只回傳該角色等級切得出來的寶石 |
| `verify_build` | 加 `character_level`：等級不夠的寶石、基底、詞綴階級列在 `too_early`，附最早可用的等級 |
| `path_to` | 加 `by_stage`：依目標列出的順序點，並用 `campaign_stages` 的各階段點數切段，回傳每段點到哪（實作時由 `budgets` 改為 `by_stage`：上限直接取自資料，不由模型傳入） |
| `export_pob` | 加 `stage`：等級、天賦點、昇華點、輔助數量都套用該階段上限；**稀有裝備詞綴改用物品等級 ≤ 角色等級的最高階**（不再一律最高階）；精魂只算到該階段的任務。一份匯入碼內含**每個階段各一個天賦樹**（PoB 的多重天賦樹），技能與裝備是最後階段的 |
| `items_by`、`modifiers_for` | 不用改，已有 `max_level` |

沿用：`gem_level_and_needs`（`build_tools.py:1512`）、`pob_level`、`_spirit_plan`、`quest_spirit`。

### 4. 流派流程（`build_workflow.py` 與 `skills/poe2-advisor/SKILL.md`）

- 預設目標是打通章節。使用者指定的等級高於章節結束等級，或說要後期／輿圖流派時，走現有流程（不變）。
- 步驟：先呼叫 `campaign_stages` → 以最後階段的上限排出成品（技能、天賦、裝備）→ 往回排每個階段：當下切得出的技能與輔助（受插槽數限制）、何時換成主技能、天賦點到哪、基底與詞綴、精魂怎麼用、昇華何時拿、這一章不能漏的獎勵 → `verify_build`（帶等級）→ `path_to`（帶 `by_stage`）→ `export_pob`（帶 `stage`）。
- 回答的格式：每個階段一段，段內固定順序（等級與點數 → 技能 → 天賦 → 裝備 → 精魂／昇華 → 任務獎勵）。
- 王的打法、手感等經驗性的內容不寫；被問到時說明本機資料沒有。
- 天梯比較保留，但註明天梯角色是後期角色，只比主技能與昇華的選擇；天梯沒有資料時直接說沒有。

### 5. 文件與版本

README（中英）說明預設是章節流派與如何要後期流派；`docs/tools*.md`、`docs/data*.md`、`docs/flow/` 的流程圖、ROADMAP、CHANGELOG；版本 0.13.0。

## 錯誤處理

- 章節資料不存在或過舊：`campaign_stages` 回報需要 `update campaign`，流派流程退回現有做法並說明原因，不猜測階段。
- poe2db 章節頁的格式變了（例如 1.0 上線）：筆數檢查（`expect_min`）不過就不覆寫舊資料，回報哪一頁有問題。
- 某階段沒有任何切得出的技能、或裝備沒有該等級的詞綴：照實列出，不補上等級不符的東西。

## 測試（全部用 `tests/fixtures/` 的合成資料）

- 單元：
  - 章節頁與 `QuestRewards` 的解析；章節數量不同時（4 章 + 插曲、6 章）都能產生階段表。
  - `campaign_stages` 的點數、昇華點、精魂、插槽數計算；邊界：試煉區域等級剛好等於階段等級、任務沒有區域等級。
  - `gems_by` / `verify_build` 的等級篩選（剛好達到需求等級、差 1 級）。
  - `path_to` 的 `by_stage`：上限小於路線、等於路線、目標在章節之後。
  - `export_pob` 的 `stage`：詞綴取到的階級不超過等級；沒有任何階級可用的詞綴列在 `not_exported`；多重天賦樹的點數各自不超過上限。
  - 不帶新參數時，所有既有測試結果不變。
  - 章節問答：區域與任務的中英文合併；同名任務出現兩次（「黑暗中的秘密」）不重複也不遺漏；`lookup_entity` 找得到區域、任務、王；`campaign_by` 依獎勵文字篩選；查無名稱時回傳候選。
- 整合：MCP 對話走完章節流程，匯入碼解碼後每個天賦樹的點數正確；章節問答的三種問題各走一次。
- 實測：在 Claude Code 請它生成一個章節流派，匯入你的 PoB 檢查各階段天賦樹與等級。
- 交付：測試報告、複查報告（改動較大，請獨立 reviewer 看一次）、CHANGELOG。

## 驗收

1. 沒指定等級時，得到分階段的章節流派；每個階段的等級、天賦點、昇華點、寶石等級、裝備都不超過該階段的上限，且都有來源。
2. 指定 90 等或說要後期流派時，結果與現在相同。
3. 匯入碼可匯入 PoB，內含每階段的天賦樹，裝備數值是該等級出得了的階級。
4. 更新 `campaign` 資料後，階段表跟著資料變（不需要改程式就能容納第 5、6 章）。
5. 用中文或英文問章節細節（「第 2 章哪些任務給天賦點？」「奧格姆宅第幾等、王是誰？」「險惡之地的獎勵？」），回答來自本機紀錄並附 poe2db 連結；問王的打法時，回答會說本機資料沒有。

## 不在範圍內（第一版）

- 每個階段各一組技能與裝備的匯入碼（第一版只有天賦樹分階段；你看過後再決定）。
- 王的打法、刷怪路線等遊玩經驗；傳奇裝備搭配與裝備製作（已在 ROADMAP）。
- 輿圖／後期內容的階段。
- 1.0 的資料：上線後更新資料再確認，必要時另開修正。

## 實作後的補充（2026-11-14）

- 獨立複查後的修正：昇華在 PoB 沒有 id 時章節匯出不再遺失天賦樹；插曲頁消失（1.0）時視為沒有插曲，不讓更新失敗；
  章節頁含有插曲頁八成以上的區域即視為插曲，插曲頁有區域卻沒有章節對應時拒絕寫入；輔助寶石清單只跟隨帶等級的物品、最多 10 頁；
  Lua 解析處理跳脫字元、註解與巢狀表。
- 早期階段的天賦樹，屬性點依最後階段的技能與裝備需求分配（第一版只切天賦樹）。
- PoB 沒有放進任何章節的獎勵（尾聲）計入最後階段；技能與精魂寶石的階級以該寶石等級所需的角色等級起算（未使用未切割寶石的掉落等級）。兩者都寫在 `campaign_stages` 的說明中。
