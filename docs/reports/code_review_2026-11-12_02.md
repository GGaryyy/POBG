## Quality assessment

- Checked against PoB 0.23.1: `Item.lua` `ParseRaw` reads our text for all three rarities (a
  normal item is looked up by its first line; `Implicits: N` takes the first N lines);
  `ItemsTab.lua` slot rules; item requirements are one source each and the maximum counts, as
  our `need` does; our base requirements match PoB for 1,737 of 1,749 shared bases.
- All 17,719 modifier texts were scanned: `upper_value` leaves no stray bracket, 490 decimal
  ranges, no range with low above high.
- Privacy: only public game data and the label "POBG <slot>" are written; no ladder names.

PoB's maximum; switching on Shocked adds PoB's base shock (the boss is treated as always
shocked), Frozen also immobilises, Exposure options are ignored unless PoB sees a source.

| # | Severity | Finding | Resolution |

## Notes

- #6 is left out on purpose: saying which level an ideal item needs would require the game's
  item-level rule, which is not in the data; the notes already say the values are an ideal.
- The configuration rules are text patterns over the game's wording. They were audited over all
  gems and passives, but a new wording in a future patch can be missed or misread; every option
  in a code is listed with its evidence so it can be checked.
- Not counted: % increased attributes and Spirit, reduced requirements, Spirit derived from
  gear values.
- PoB marks a modifier line it cannot parse as unsupported; that can only be seen in PoB.
