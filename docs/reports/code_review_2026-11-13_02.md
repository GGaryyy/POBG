# Code Review — 2026-11-13 (0.12.0, Codex plugin)

Review by the main session; no independent reviewer was used, as planned: the change is manifests, one MCP
config file and skill text, each held by a test and checked by installing into Codex.

## Scope

`.codex-plugin/plugin.json`, `.codex-plugin/mcp.json`, `.agents/plugins/marketplace.json` (new);
`skills/*/SKILL.md`, `tests/unit/test_plugin_manifest.py`, version files, READMEs, client and data guides,
ROADMAP, changelog.

## Assessment

- The Codex manifest follows the bundled plugins on the user's machine (Codex 0.168.0): `skills` and
  `mcpServers` as paths, an `interface` block. The plugin-creator's newer "Agent Plugins 1.0" root
  `plugin.json` was not used: Codex reads `.codex-plugin/plugin.json`, and a root `plugin.json` would sit
  next to the Claude files without being needed today.
- The server file is in `.codex-plugin/`, not a root `.mcp.json`, which Claude Code would read as a project
  server and start twice. Tested.
- The Codex server has no `UV_PROJECT_ENVIRONMENT`: Codex has no equivalent of `${CLAUDE_PLUGIN_DATA}`, so uv
  builds `.venv` in the plugin's cache folder, which a plugin update replaces (the next start rebuilds it).
- Skill frontmatter keeps the Claude-only fields; Codex ignores them.

## Findings

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Medium | `update-pob` ran from `${CLAUDE_PLUGIN_ROOT}`, which Codex does not expand | The skill names the folder for each host; Codex resolves relative paths against the `SKILL.md` folder |
| 2 | Medium | A local install copies the whole folder, `.venv` and `output/` included | Documented: install from a clean clone |
| 3 | Low | `disable-model-invocation` (only the user may start `update` and `update-pob`) has no Codex counterpart, so the model could start them there | Not changed: `update` asks before more than 60 pages, `update-pob` asks before downloading; noted here |
| 4 | Low | The server command is plain `uv`; Codex must find uv on PATH | Same as the Claude plugin; the client guides give the full path for the manual setups |
| 5 | Info | Command names match; the calling sign differs (`/` in Claude Code, `$` in Codex) | Each host's rule; the READMEs give both |

## Verdict

Approved with Notes: the notes are #3 and #4. A chat through the Codex plugin was confirmed by the user (`$pobg:status`).
