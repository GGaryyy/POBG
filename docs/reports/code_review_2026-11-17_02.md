## Quality assessment

- **Readability and structure:** the collector follows the campaign and currency collectors (parse →
  merge → check → write). Map stages are built in the campaign stages' shape, so `path_to(by_stage)`,
  `verify_build(character_level)` and `export_pob(stage)` needed no change. The search-string module
  keeps the piece rules in small functions (`_pieces`, `_rank`, `shortest_piece`, `pack`, `_avoided`).
- **Data honesty:** stage limits, area levels and the penalty come from the page; the endgame trial
  levels are hand-checked and dated in the catalog. The review caught a hand-written Chinese label that
  was invented ("已汙染"); labels now come from the page. What the data cannot prove (that a build clears
  Tier 16, that a string works in the game) is stated in the answers and docs.
- **Thread safety:** the reviewer found the lock order always campaign → atlas, never reversed, and a
  failed atlas load is rebuilt after `update_data` by a new `BuildTools`.
- **Performance:** a gear string on real data takes about 0.4 s (all substrings of the wanted
  modifiers against one item class's modifiers and bases); a map string a few milliseconds.
- **Security:** pieces never hold regular-expression characters, quotes or `!`; the strings are text
  returned to the model, never run. Every URL is built by `resolve_url` on poe2db. `pip-audit`: no known
  vulnerabilities. `bandit` on the three new files: no findings. No secret in the new files or catalog.

## Test-quality audit

The reviewer named: no round trip from `waystone_mods` to `search_string`; only `{not json` as bad data;
no target without Chinese; no multi-line gear template; penalty table edges (64, 65, empty) untested; the
update's "changed shape" and write-failure branches untested; no call through the MCP server; hollow
assertions (a constant compared with a constant, a Chinese gear test checking only that a string exists,
a "tiers share a piece" test with one line, `left_out` checked only for being non-empty); a collector
test failing for several reasons at once. Each now has a test or an exact assertion. Still thin: the
synthetic waystone set has five modifiers, so `MAX_AVOID_MATCHES` and piece choice are mostly exercised
on real data (checked by hand, examples in the plan addendum), not in tests.
